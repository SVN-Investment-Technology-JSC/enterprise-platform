# Notification Realtime v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Triển khai Notification Center realtime, bền vững và tenant-safe cho toàn bộ tenant module của Enterprise Platform.

**Architecture:** `notification-worker` consume domain event và ghi notification + sequence event trong tenant PostgreSQL; `realtime-api` cung cấp REST/Socket.IO và emit delivery event qua Valkey. RabbitMQ và transactional outbox bảo đảm retry; client dùng sequence sync khi vượt cửa sổ Socket.IO recovery.

**Tech Stack:** Nx 23.1, Node 24.11, NestJS 11, PostgreSQL 17, RabbitMQ 4, Socket.IO 4.8.4, Redis Streams adapter 0.3.1, Valkey 9.1.2, React 19, Next.js 16.

**Spec:** `docs/superpowers/specs/2026-10-01-notification-realtime-v1-design.md`

## Global Constraints

- Chỉ `tenant-user`; không Platform Admin, email, Web Push hoặc chat trong v1.
- WebSocket-only tại `/realtime/socket.io`; cookie HttpOnly và Origin allow-list.
- Notification 90 ngày, delivery log 7 ngày, recovery Socket.IO 2 phút.
- 5.000 concurrent sockets; p95 event→socket <2s và REST p95 <300ms.
- Mọi behavior mới theo TDD; mọi target chạy qua `pnpm nx`.
- UI tuân thủ `ui-design`, không emoji và không HTML `<select>`.

## Review Focus

- Tenant bị disable/xóa trong lúc event đang retry: không emit và message được kết thúc có kiểm soát.
- Sequence gap sau read-all hoặc aggregation: client nhận reset/summary đúng, không kẹt unread.
- Reconnect đồng loạt sau Valkey restart: jitter và auth không tạo thundering herd.
- Recipient mất quyền sau lúc notification được tạo: feed không làm deep link vượt authorization.
- DST/timezone thay đổi quanh scheduler: một emission duy nhất cho mốc nghiệp vụ.
